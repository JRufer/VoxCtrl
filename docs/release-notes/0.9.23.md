**Long dictations to a server work.** A dictation is sent to the server while
you speak, and that upload was under the server timeout (30 seconds unless you
changed it) from its first moment. Speak for longer than the timeout and the
dictation failed, or went to your fallback engine, however quickly the server
would have answered. The timeout now starts when you stop speaking: it is how
long the server gets to answer, not how long you may talk.

**One missed check no longer counts as an outage.** The app checks on its
server every 15 seconds. A single check lost to a busy server or a moment of
bad Wi-Fi used to mark the server unreachable: live text stopped in the middle
of a dictation, and with a fallback engine set the next dictations went to it.
The app now looks again three seconds later and only then calls it
unreachable. A dictation that cannot connect at all still says so at once.

**Recordings have a length limit.** A recording nobody stops, such as a toggle
shortcut pressed once and forgotten, grew without limit. It now stops by
itself after 10 minutes, transcribes what was said, and tells you why. Change
it under Settings → Audio → Longest recording (0 for no limit), or with
`audio.max_recording_secs`.

**A crash inside the speech engine no longer stops dictation for good.** If
the engine failed badly during one pass, the part of the app that transcribes
stopped with it: the microphone level still moved, but nothing was
transcribed until a restart. That pass now fails by itself and the next one
works. Such a crash is also written to the log with the place it happened,
which it was not before.

If dictation stops while you are still holding the shortcut, or produces
nothing, please send the log (Settings → Bug Report): this release is built to
say what happened.
