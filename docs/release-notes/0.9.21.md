**The AppImage starts again on Arch and other rolling distributions.**
v0.9.20's AppImages could stop at launch with:

```
voxctrl: symbol lookup error: /usr/lib/libwebkit2gtk-4.1.so.0: undefined symbol: manette_device_get_mapping
```

The AppImage uses your system's WebKitGTK when you have one, but it still
shipped its own older copy of `libmanette`, a library WebKitGTK depends on.
Your WebKitGTK picked up that old copy and failed. The AppImage now prefers
your system's copies of all of WebKitGTK's own dependencies too, and still
carries them for desktops that have no WebKitGTK at all.

If you're stuck on v0.9.20, this starts it until you update:

```bash
LD_PRELOAD=/usr/lib/libmanette-0.2.so.0 ./VoxCtrl-linux-x86_64-vulkan-webgpu.AppImage
```

**For contributors.** A new check, `scripts/check-appimage-webkit-deps.sh`,
fails the AppImage build if a library that only the bundled WebKitGTK needs is
left where it could shadow the system's copy.
