**New: `voxctrl-server`, for running the speech model on another machine.** A
laptop no longer has to hold the model it dictates with. `voxctrl-server` is a
headless program — no window, no tray, no audio device — that loads one of
VoxCtrl's own engines (whisper.cpp, Moonshine or Parakeet) on a desktop or home
server and serves it to the app over your network. The app connects through the
Remote Speech Engine it already has: in **Settings → Engine**, set **Backend**
to **Remote Speech Engine (OpenAI API)** and enter the server's address and API
key. Hotkeys, the microphone, the overlay and typing the result all stay on
your computer; only transcription moves. Several computers can share one
server.

It runs in Docker (a Dockerfile and Compose file are in `packaging/docker/`) or
as a systemd service (`packaging/systemd/`). On first start it downloads the
model you chose, generates an API key and prints it once. The new
[VoxCtrl Server](https://github.com/JRufer/VoxCtrl/blob/master/docs/server.md)
guide covers installation, connecting the app, every setting, security and
troubleshooting.

Things to know about this first version:

- **Both are built from source for now.** There is no published Docker image or
  prebuilt server binary yet; the guide gives the commands.
- **The connection is not encrypted.** The server speaks plain HTTP, so use it
  on a network you trust, or behind a VPN or an HTTPS reverse proxy. Every
  request needs the API key.
- **Only speech recognition moves to the server.** S1-mini cleanup, the LLM
  step and text-to-speech still run in the app.
- **No live text and no fallback.** Overlays cannot show words as you speak
  while a remote engine is selected, and if the server is unreachable dictation
  fails until it is back. Both were already true of the Remote Speech Engine.
- **GPU use in Docker is experimental** and has not been tested on real
  hardware. Parakeet and Moonshine are fast on a CPU and need no GPU.

**Fixed: every hotkey could stop working after the setup wizard.** Clicking
the shortcut recorder in the wizard and then moving to another step without
pressing a key left the app ignoring all hotkeys — the recorder switches them
off while it listens, and that path never switched them back on. Nothing on
screen said so, and only restarting VoxCtrl cured it. Leaving the step,
finishing the wizard, and closing the wizard or Settings window now all switch
them back on. The same could happen in Settings → Hotkeys by closing Settings
mid-recording, and is fixed the same way.

**Changed: a config section may name only some of its keys.** The
`engine.whisper_cpp`, `engine.moonshine` and `engine.parakeet` sections of
`config.json` used to need every key present, so a hand-edited file that left
one out fell back to defaults for all of its engine settings. A missing key
now takes its own default and everything else in the file is kept.
