**New: text-to-speech can run on the server.** A VoxCtrl server can now do the
speaking for its clients. It synthesizes with an engine and voice set on the
server and the client plays the audio, so the client loads no TTS model.

- **On the server:** set `VOXCTRL_SERVER_TTS=true` with
  `VOXCTRL_SERVER_TTS_ENGINE` and `VOXCTRL_SERVER_TTS_VOICE` (Docker), or add a
  `[tts]` section to `server.toml`, and restart. The section takes the same
  keys as the app's own TTS settings. Piper, eSpeak, Pocket-TTS, Kitten TTS 2,
  Breeze-TTS-2 and VoxCPM2 are supported; Inflect-Micro is not yet. A Docker
  image has to be rebuilt for this release.
- **On each client:** in **Settings → TTS**, set **Engine** to **VoxCtrl
  server**. The panel under it shows the engine and voice the server speaks
  with, or what to change if it does not speak. The server used is the one
  under Engine → Remote Speech Engine Settings.

Things to know:

- Every client of a server hears the server's voice. Voices cloned on a client
  can't be used through the server yet.
- Speed, the stop key, pronunciation snippets and custom vocabulary still apply
  on the client.
- The server synthesizes a whole passage before playback starts, so long
  passages begin later than with a local engine.
- If the server can't be reached, nothing is spoken and the reason is shown.
- With the server engine selected, **Clean up models** treats local TTS models
  as no longer in use.

The server's endpoint is `POST /v1/audio/speech`, in the shape of OpenAI's, and
returns WAV. Text-to-speech is off by default at both ends. The full guide is
in `docs/server.md` under "Text-to-speech on the server".
