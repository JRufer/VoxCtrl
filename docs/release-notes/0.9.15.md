**New: encrypted connections to a VoxCtrl server, and pairing codes.**

- **Encryption (optional, off by default).** Set `VOXCTRL_SERVER_TLS=true` (or
  `[tls] enabled = true` in `server.toml`) and the server answers HTTPS only,
  with a certificate it makes for itself on first start. Dictation audio,
  cleaned-up text, speech, uploaded voices and the API key are then encrypted
  on the network.
- **Pairing codes.** `voxctrl-server --pairing-code` prints one code holding
  the server's address, API key and certificate fingerprint. Paste it into the
  new **Pairing code** field under **Settings → Engine → Remote Speech Engine**
  and everything is filled in and tested. Works without encryption too, as a
  shortcut for the address and key.
- **The app talks only to your server.** A paired app accepts the one
  certificate named in the code, shows `🔒 Encrypted` with its fingerprint, and
  refuses to fall back to an unencrypted address.

Turning encryption on needs both the server and the app on 0.9.15, and each
app paired again; until then a client with a fallback engine dictates locally.
Servers and clients that leave it off work as before. See
[Encryption](https://github.com/JRufer/VoxCtrl/blob/master/docs/server.md#encryption).
