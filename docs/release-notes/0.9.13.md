**Fixed: repeated spoken responses through the server could freeze the overlay
and lose dictation.** With the TTS engine set to VoxCtrl server, starting to
talk again while a response was still being synthesized stopped the audio on
the client but nothing else: the client kept waiting for the server, and the
server kept synthesizing sentences nobody would hear. After two or three in a
row the server was busy with stale speech, so the next dictation was
transcribed late or timed out, and the next response did not start.

- Stopping speech now gives the request up at once and closes the connection.
- The server skips a speech request whose client has gone before its turn
  came.
- On the server, neural speech synthesis now runs at a lower priority than
  transcription, so a dictation that arrives mid-sentence is transcribed first.

A sentence the server has already started synthesizing still runs to its end.
On a slow engine (Kitten TTS 2 on a CPU takes tens of seconds per sentence)
that can still delay the next response; a faster engine such as Piper, or a GPU
on the server, is the remedy for that.

Both the app and the server changed: update both.
