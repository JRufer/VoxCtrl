**New: choose the server's speech engine and voice from the client, and use
your own voices on it.** With the TTS engine set to **VoxCtrl server**, the TTS
tab now has two pickers:

- **Engine**: the engines the server has set up. The server's owner lists them
  (`VOXCTRL_SERVER_TTS_ENGINES=kitten_tts_2,piper`, or `[speech] engines` in
  `server.toml`); a client can only choose among those and can never make the
  server download anything.
- **Voice**: the server's default, the engine's own voices, and, with
  Pocket-TTS, Kitten TTS 2, Breeze-TTS-2 or VoxCPM2, **your own voices**: the
  clips in your cloned voices folder.

Picking one of your voices sends it to the server. It is stored for your
computer only, so other clients of the same server neither see it nor can speak
with it, and deleting the clip on your computer removes it from the server at
the next sync. Each client's choice travels with its requests, so several
clients can use different engines and voices on one server.

**Fixed: the neural TTS engines could not start in the Docker image.** Kitten
TTS 2, VoxCPM2, Breeze-TTS-2 and Pocket-TTS failed there with
`GLIBC_2.43 not found`: the image was based on Debian 13, which is older than
the speech runtime those engines need. The image is now based on Ubuntu 26.04.
Rebuild it with `docker compose up -d --build`; your models, voices and API key
are in the volume and are kept.

Both ends need 0.9.11 for the pickers. An older server still works with a newer
client and offers its one engine without a choice.
