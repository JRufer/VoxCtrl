**A word repeated over and over is stopped.** A speech model can stick on one
word and write it again and again until it runs out of room: `send it to the
the the the the the…`. Nothing caught that before. Now:

- **Every transcript is checked.** One word five or more times in a row, or a
  phrase of up to six words four or more times, is cut back to a single copy.
  Shorter runs are left alone, since people do say "no no no no". This runs
  in the app and on the server, for whichever engine produced the text.
- **Parakeet** notices when it is stuck on one moment of audio and moves on,
  instead of writing up to ten copies there.
- **Moonshine** may only write as much as the audio has room for. A half
  second clip used to be allowed 192 tokens.
- **Cleanup** (S1-mini) output is thrown away, and your words delivered as you
  said them, when it comes back far longer than what you said or repeating
  itself.

The log says when any of these fires, with counts and never your words. If you
still see repeats, a bug report with that log will show which part produced
them.

**A dropped connection no longer cuts a dictation short.** If the upload to a
server broke while you were still speaking, VoxCtrl sent the server only what
it had so far and delivered that fragment as the whole dictation. It now waits
until you finish and sends the whole recording.

**Dictations no longer wait behind live text.**

- On a server, a finished dictation now stops a live-text clip that is being
  transcribed, rather than waiting for it. A clip whose app has given up on it
  is stopped too.
- In the app, Parakeet and Moonshine live-text passes now stop the moment you
  release the key, as Whisper's already did, so the final text is not held up
  by one.

**The overlay no longer shows words twice** when a server's answer to one
dictation arrives after you have started the next.

**Whisper and Moonshine models download safely.** A model is now written to
disk as it arrives, not held in memory first (`large-v3` is 3.1 GB), and a
download that is cut off no longer leaves a broken file that looks installed.

**Docker and source builds work again.** v0.9.21's `Cargo.lock` was out of
step with its version number, so every build that passes `--locked` failed:
the server's Docker image and the AUR source packages. The lockfile is fixed.

**For contributors.** CI now fails a pull request whose `Cargo.lock` is out of
date, and `scripts/bump_version.sh` updates the lockfile itself.
