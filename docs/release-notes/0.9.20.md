**More hardening ahead of 1.0.** The second half of the pre-release review.

**On a server, dictations come first.** The server's model transcribes one
request at a time. It now puts finished dictations ahead of live text:

- **Live text never delays a dictation.** A live-text clip runs only when the
  model is free and no dictation is waiting; otherwise it is skipped, and the
  next clip carries more of the recording anyway. With two devices on one
  server, one person's live text no longer holds up the other's dictation.
- **A full queue says so.** Up to 8 dictations may wait. A ninth is answered
  "The server is busy", and the app gives that dictation to its fallback
  engine instead of waiting minutes.
- The app marks its live-text clips for the server. Other clients, and older
  apps, are treated as before.

**Stalled connections are closed.** The server now drops a connection that
has not sent a request's headers within 30 seconds, and a request whose upload
pauses for 30 seconds. Dictations streamed while you speak are not affected.

**Clearer wording about uploaded voices.** The server docs no longer call a
client's uploaded voices private. Each app sees only its own, but anyone with
the server's API key who learns an app's id could use them.

**The log no longer grows without limit.** Once `startup_errors.log` passes
1 MB, VoxCtrl cuts it back to its most recent 256 KB when it starts.

**For contributors.** The Rust code is formatted with `rustfmt` (120-column
lines, set in `rustfmt.toml`), and CI now checks formatting and runs clippy
with warnings as errors.
