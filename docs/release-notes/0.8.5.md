**New: cleanup styling per app.** S1-mini dictation cleanup can now use a
different style depending on where you're dictating: casual in Slack, formal
in your email client, and the usual style everywhere else. Add rules in
Settings → Post-Processing → **Styling per app**. **Detect app** gives you
three seconds to click into the app you want, then adds it for you. The
focused app is read from its window class on X11, Hyprland, Sway and KDE
(with `kdotool` installed), and from its program name on Windows. GNOME
can't report it, so the usual style always applies there.

**New: dictation history.** Settings → **History** lists what you've
dictated recently, newest first. You can search it, then copy an entry, type
it again into the window you were using, read it aloud, send it to any output
target, or delete it. History is private by default: it's kept in memory
only, it holds at most 50 dictations from the last 24 hours (both
adjustable), and it's gone when VoxCtrl quits.

**Keeping history between restarts is optional, and encrypted.** Turn on
**Keep history between restarts** and the history is saved encrypted. The key
lives in your desktop keyring (KWallet or GNOME Keyring), or is protected by
Windows data protection on Windows, so another program that copies the file
can't read it. If no keyring is available, VoxCtrl won't save the history
unencrypted; it keeps it in memory only and shows why. Turning the setting
off deletes the file and the key.

**New: "Don't keep in history" per target.** Tick it on any output target,
in the target editor under Privacy, for dictation you'd rather not have kept,
such as a password manager or a private chat.

**New MCP tools.** `set_target` lets an MCP client choose which output target
dictation goes to. `get_recent_transcripts` lets it read recent dictations,
but only after you turn on Settings → History → **Let MCP clients read recent
dictations**, which is off by default.

**Changed: the MCP socket moved** to your private runtime folder
(`$XDG_RUNTIME_DIR/voxctrl-mcp.sock`). In the shared `/tmp`, another account
on the computer could claim the name first and pose as VoxCtrl.
`/tmp/voxctrl-mcp.sock` still works, as a link to the new location, so
existing MCP client setups need no changes.

**Fixed: transcripts in the log.** VoxCtrl logged the full text of every
transcription and of text sent to text-to-speech, and that log can end up in
the system journal. It now logs only word and character counts.
